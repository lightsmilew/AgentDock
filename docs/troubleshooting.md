# 常见问题

## 已安装 Agent，但状态为未安装

点击“重新检测”，必要时启动后台磁盘搜索。未登记的便携版可在展开区域“定位程序”；Roo Code 使用“定位扩展”。请选择真实主程序或扩展目录，不要选择安装器、失效脚本或只剩配置的目录。

桌面版与独立 CLI 分别检测，Cursor.exe 存在不代表 `agent` CLI 已安装，Codex、Claude Code 同理。仅剩 Skill 或配置目录不作为已安装证据。

检测支持自定义盘符和中文路径。权限不足或未登记便携版仍可能需要手动定位。专用测试 fixture 被过滤，普通项目目录和 `.development` 内的真实应用不一律排除。

## 启动按钮灰色或只打开 PowerShell

检查桌面路径与 CLI 路径，启动 CLI 需要有效命令入口；桌面软件使用桌面启动入口。

路径存在但不可用时，查看架构、Windows 版本、Node 版本、占位文件或缺少依赖的提示，通过官方方式修复。安装退出码为零后仍需有效入口和版本校验。

Qwen 支持 npm 与独立运行时入口，独立安装检查 bin 目录及 `QWEN_INSTALL_BIN_DIR` / `QWEN_INSTALL_ROOT`。不要把桌面版内不可独立运行的脚本任意当作 CLI。

## Windows 显示不兼容或程序闪退

管理器检查 PE 格式、机器架构、最低子系统版本与相关运行环境。厂商还可能要求更高系统版本、CPU 指令或组件，文件检查不能保证运行成功。

Claude Code 的 shell 占位文件不是 Windows EXE。不完整 npm 安装缺少可选依赖或安装脚本时，应通过官方方式重新安装。管理器不承诺绕过厂商未支持的系统或 CPU 限制。

保留报错、实际路径和安装日志用于排查，不以启动测试文件替代真实安装验证。

## 安装目录无法指定，或取消后还有文件

Codex 与 Claude 的 Store / MSIX 桌面安装位置由 Windows 管理。其他支持目录参数的桌面版使用所选独立目录，CLI 沿用官方方式。

取消停止当前安装进程组，但已完成的文件和系统登记可能仍在。刷新后按实际结果决定是否卸载，避免删除共享父目录。

## 卸载后仍发现路径

区分有效程序与保留配置。默认卸载保留用户数据，需要清除时勾选“彻底清理用户数据”并核对范围。Cursor 可能存在更新子目录或缺失登记；Roo 可能有多宿主、多版本和便携扩展，应查看实际目标。

文件被占用时关闭对应 Agent 或编辑器后重试。未核实文件、项目和其他扩展的数据不因名称相似而删除。

## Skill 无法部署或没有出现在 Agent 中

- 确认 `SKILL.md` 和支持文件有效，目标无冲突或权限错误。
- 项目级部署先在设置选择有效项目目录。
- WorkBuddy 通过原工具导入 ZIP；Trae 当前仅有已核实的项目级 Skill 目录。
- 已位于目标的 Skill 不需要再次导入或复制；原工具可能需要刷新或重启。
- 外部目录嵌套过深时，可导入具体 Skill 根目录。

## 配置成功，但模型没切换

核对协议、API、真实模型 ID、默认项和配置优先级。项目设置、会话参数、Roo 模式绑定和企业策略可能覆盖默认项。

Cursor 启动档案作用于从管理器启动的 CLI，桌面账号模型仍在原工具设置。Copilot / OpenHands 的环境注入也须从管理器启动。CodeBuddy / WorkBuddy 默认模型在原工具选择，ZCode 旧配置先由新版迁移。

401 / 403 通常检查凭据与权限，404 检查端点、协议和模型 ID，429 检查配额与限流，最终以服务响应内容为准。分享日志前隐藏密钥和个人信息。

## 官方链接打不开

从 [来源与核查说明](source-audit.md) 查找入口。外部站点可能迁移、限制访问或临时不可用，历史成功不代表当前可访问。Harness 有官网、官方仓库与文档备用入口，不使用同名社区产品替代。
